2. CONFIRMED DEFECTS FOUND AND FIXED
============================================================

A) SECOND CURRENCY CONVERTER WAS ACTUALLY UNWIRED
Problem:
The Money tab has a second converter using currencyAmount/currencyFrom/currencyTo/currencyResult/currencyStatus, but no JavaScript was connected to it. Previous converter fixes targeted the different Finance converter, which is why the Money converter could remain stuck on "Loading rates...".
Fix:
- Added independent Money-tab converter wiring.
- Added 23 currency choices.
- Uses cached rates first.
- Uses live Open ER source, then Frankfurter v2 fallback.
- Displays a real failure state instead of hanging forever.
File:
- js/nexusnova-allinone-hub-v1.js

B) SPLIT BILL USED THE WRONG ELEMENT ID
Problem:
The function read billAmount while the visible Money tab uses moneyBillAmount.
Fix:
- Corrected the ID.
- Runtime result verified: bill 1000 + 10% / 2 = total 1100, each 550.
File:
- js/nexusnova-allinone-hub-v1.js

C) MONEY EXPENSES WERE RENDERED INTO THE WRONG LIST
Problem:
The Money module wrote expenses into expenseList belonging to another tools surface instead of moneyExpenseList.
Fix:
- Corrected rendering target.
File:
- js/nexusnova-allinone-hub-v1.js

D) VOICE MODULE COULD RECURSE UNTIL STACK OVERFLOW
Problem:
If speechSynthesis.getVoices() initially returned an empty array, loadVoices() and chooseVoice() could call each other recursively.
Fix:
- Removed recursive cycle.
- Empty voice state now returns safely and can retry later.
File:
- js/nexusnova-natural-voice-v1.js

E) DOCUMENT IMAGE ANALYSIS PASSED THE WRONG OBJECT
Problem:
Mega document analysis passed a File object to handleAIImage(), while handleAIImage expects an input element containing .files[0].
Fix:
- Passes the actual file input element.
File:
- js/nexusnova-mega-merge-v1.js

F) VOICE COMMAND "START MINING" TARGETED A NONEXISTENT BUTTON
Problem:
Voice command tried startMiningBtn; actual button is mineBtn.
Fix:
- Corrected start command.
- Removed false "stop mining" behavior; the existing secure 24-hour flow auto-finishes and currently has no manual early-stop UI.
File:
- js/voice-commands-v1.js

G) TOP-100 MARKET/WALLET HANDLER RACE
Problem:
The Top-100 module installed its handlers during parsing, but deferred page2 module code could overwrite them with older 20-row handlers later.
Fix:
- Top-100 handlers are reasserted after DOMContentLoaded and again at window load.
- Runtime tests confirmed 100 Market rows and 100 Wallet rows both initially and after later refreshes.
File:
- js/nexusnova-top100-live-fix-v3.js

H) DEPOSIT/WITHDRAW HANDLER RACE MADE SECURE BACKEND PATH LOSE
Problem:
wallet-actions-v2 intended to use Cloud Functions, but page2 module could overwrite handleDeposit/handleWithdraw with older direct-Firestore handlers. Firestore rules deny those direct writes, making the legacy path fail.
Fix:
- Secure callable wallet actions are reasserted after module execution and at window load.
- Runtime verified final handlers are wallet-actions-v2 deposit()/withdraw().
File:
- js/wallet-actions-v2.js

I) CALLER/PHONEBOOK MODULE HAD A REAL SCOPE CRASH
Problem:
Caller code was appended outside its earlier IIFE but referenced private helpers load/save/uid/esc. This produced ReferenceError at runtime.
Fix:
- Caller section now has its own scoped helpers.
- Caller lookup runtime-tested.
File:
- js/nexusnova-tools-hub-v1.js

J) CALLER LOOKUP COULD NOT SEE THE ACTUAL FAMILY/EMERGENCY STORAGE KEYS
Problem:
Family Hub and Emergency module stored contacts under different keys than Caller Lookup searched.
Fix:
- Caller now recognizes actual Family Hub and Emergency keys plus compatible fallbacks.
- core failsafe emergency key normalized.
Files:
- js/nexusnova-tools-hub-v1.js
- js/core-failsafe.js

K) NEW FIRESTORE USER PROFILE MISSED A RULE-PROTECTED FIELD
Problem:
New profile did not include dailyRewardStreak even though update rules expect reward fields to exist and remain protected.
Fix:
- Added dailyRewardStreak: 0 to new profile creation.
- Sign-up harness verified full payload.
File:
- index.html

L) SERVICE WORKER / PWA COULD SERVE STALE CODE AND HAD INCOMPLETE OFFLINE ASSETS
Problem:
Older Android service worker was cache-first and root/Android versions were out of sync. Active assets/icons were incomplete.
Fix:
- Unified service worker to network-first same-origin behavior.
- Cache bumped to nexusnova-shell-v5-deep-audit.
- Active CSS/JS/manifest/icons added to shell cache list.
- Root and Android service worker now match.
File:
- sw.js

Hosting public directory is "." and ignore rules were too small, so Android source, Cloud Functions source, package metadata and audit TXT files could be included in hosting deployment.

O) ANDROID WEBVIEW BRIDGE BOUNDARY WAS TOO BROAD
Problem:
The native JavaScript interface contains phonebook/caller methods, while the same WebView previously allowed arbitrary http/https navigation. Remote pages/frames should not share a privileged native bridge.
Fix:
- Only bundled file:///android_asset/www/ navigation stays in the privileged WebView.
- Remote/custom navigation is handed to external apps.
- Cleartext traffic disabled.
- Android in-app browser modules now open remote web content externally when NexusAndroid is present instead of loading it into the privileged iframe.
- Added a small validated NexusAndroid.openExternal(http/https only) bridge method.
Files:
- NexusNovaAndroid/app/src/main/java/com/nexusnova/app/MainActivity.kt
- NexusNovaAndroid/app/src/main/java/com/nexusnova/app/NexusBridge.kt

P) PRICE ALERT LOCAL-STORAGE XSS PATH

- Mega news links validated too.

4. WORKING CODE, BUT LIVE EXTERNAL SERVICE STILL REQUIRED
============================================================
These cannot truthfully be called fully production-verified from this archive alone:

- Email/password + Google authentication against the real Firebase project:
  Code is present. Local auth shell/profile creation has been exercised with Firebase stubs. Live Firebase auth was not executed from this audit environment.

- Production reCAPTCHA / abuse protection:
  index.html intentionally uses Google's official reCAPTCHA TEST key. It is useful for UI testing but is not production anti-abuse protection. Replace with a production site key and add server/App Check protection before launch.

- Live Market/Wallet prices:
  Code has CoinGecko/Binance fallbacks and Top-100 behavior was runtime-tested using deterministic responses. Third-party live availability/rate limits remain external dependencies.

- Live Currency/Gold/FX:
  Both converter code paths have fallback/cache logic. Live provider availability remains external.

- Deposit addresses:
  getDepositAddress intentionally refuses to invent an address. It requires NEXUSNOVA_DEPOSIT_ADDRESSES_JSON in the Cloud Functions environment.

- Withdrawal:
  Current backend creates a pending_review request only. It does NOT transfer funds. This is safer than faking a transaction, but it is not a production custody/withdrawal system.

- Android caller ID:
  Native caller-screening code, role flow and phonebook bridge are present. A real Android build/device/ROLE_CALL_SCREENING test is still required.
