# NexusNova bug audit — 24 Aug 2026

Working branch: `nexusnova-latest-full-apk-recovery-20260823`

This ledger separates code-confirmed bugs from phone verification. A code fix is not a phone PASS until it is physically exercised on the Android device.

## Fixed in source / OTA path

### Settings share used a local WebView URL
- Symptom: Settings shared/copied `location.href`, which can be an `appassets.androidplatform.net` local Android URL.
- Fix: share/copy the public NexusNova app URL instead.
- Source commit: `87893c64e1072a90b92676c3a6d671cbc2d4afbc`.
- Phone verification: pending.

### FCM silent refresh could miss the already-fired window load event
- Symptom: the Notifications module is lazy-loaded after startup, but the old silent refresh only attached a future `load` listener. If `load` already fired, refresh never ran.
- Fix: run the delayed refresh immediately when `document.readyState === 'complete'`; otherwise wait for `load` once.
- Source commit: `d0e50dd50aa00b342c658c5df763e7dd39713e69`.
- Phone/browser verification: pending.

### One app renderer could tear down the whole app-screen transition
- Symptom: a synchronous renderer exception propagated through the app route and could leave the app screen unavailable.
- Fix: validate renderer output and isolate synchronous renderer errors behind a recoverable per-app error screen with a working back action.
- Source commits: `623e8982ce76c67b6a139801395c31a0c656e13d`, `435bdc03c8d93b65cdea499d8da6fe96d8af4da5`.
- Phone verification: pending.

### Lazy app module failure could become sticky and blank the route
- Symptom: a rejected dynamic `app-screen.js` import stayed cached in `appScreenModulePromise`, so later app opens could immediately repeat the same rejection until a full page reload. The first failed route also had no local recovery UI.
- Fix: clear the cached Promise on import rejection and return a visible Retry/Back recovery screen from the app route.
- Source commit: `2ea49f2d9a8f4e8139001ad273f65f3501625a45`.
- Phone/browser verification: pending.

### Service worker cache cleanup was origin-wide
- Symptom: activation deleted every cache key except the NexusNova cache, which could remove unrelated same-origin web app caches.
- Fix: namespace cleanup to `nexusnova-fresh-shell-*` only and bump NexusNova shell cache to v2.
- Source commit: `953f9767f6f1d6833d17e0ac7f08cae837be6cee`.
- Browser verification: pending.

### Notification click could target an unrelated same-origin tab
- Symptom: `clients.matchAll({includeUncontrolled:true})` could select a same-origin client outside the NexusNova service-worker scope.
- Fix: only focus/navigate clients whose URL belongs to `self.registration.scope`.
- Source commit: `fcfdf2565b543a55b785714d2d3004cde3d459f6`.
- Browser verification: pending.

### Missing Notification API compatibility sentinel was unsafe
- Symptom: old WebViews without `Notification` received a `null` compatibility value. Code that checked `'Notification' in window` could then read `Notification.permission` and throw.
- Fix: use an explicit unsupported sentinel and make the Notifications module detect real constructor support with `typeof globalThis.Notification === 'function'`.
- Source commits: `5f29d00458cce2d482896fe17fda9ddb9062fc23`, `d2ba12b18bf07fd0e41fc6e22c1685b798dea09c`.
- Phone/browser verification: pending.

## Confirmed bugs still pending

### Wallet EIP-1193 listeners accumulate
- File: `fresh-rebuild/src/features/apps/core-apps.js`.
- Current code registers anonymous `accountsChanged` and `chainChanged` handlers every time Wallet is rendered.
- Current cleanup only unsubscribes the Firestore listener.
- Risk: repeatedly entering/leaving Wallet can accumulate duplicate provider refresh callbacks.
- Planned fix: keep stable handler references and remove them with provider `removeListener` during `root.__cleanup`.
- Do not rewrite this large core file without exact full-file/diff verification.

### Nova Internet Speed directly reparses saved JSON without a guard
- File: `fresh-rebuild/src/features/apps/premium-nova-internet-speed.js`.
- `loadPrevious()` safely catches malformed JSON, but the initialization line immediately calls `JSON.parse(localStorage.getItem(NIS_RESULT_KEY))` again without a try/catch.
- Risk: corrupted/legacy local storage can throw during renderer startup.
- Current mitigation: the new per-app renderer error boundary prevents this one tool from tearing down the full app route.
- Planned fix: parse once through a safe helper and reuse the sanitized saved result.
