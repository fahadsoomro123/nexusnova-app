# NexusNova bug audit — 24 Aug 2026

Working branch: `nexusnova-latest-full-apk-recovery-20260823`

This ledger separates code-confirmed bugs from phone verification. A code fix is not a phone PASS until it is physically exercised on the Android device.

## Fixed in source / OTA path

### Settings share used a local WebView URL
- Symptom: Settings shared/copied `location.href`, which can be an `appassets.androidplatform.net` local Android URL.
- Fix: share/copy the public NexusNova app URL instead.
- Source commit: `87893c64e1072a90b92676c3a6d671cbc2d4afbc`.
- Phone verification: pending.

### FCM silent refresh could miss the already-fired window load event
- Symptom: the Notifications module is lazy-loaded after startup, but the old silent refresh only attached a future `load` listener. If `load` already fired, refresh never ran.
- Fix: run the delayed refresh immediately when `document.readyState === 'complete'`; otherwise wait for `load` once.
- Source commit: `d0e50dd50aa00b342c658c5df763e7dd39713e69`.
- Phone/browser verification: pending.

### One app renderer could tear down the whole app-screen transition
- Symptom: a synchronous renderer exception propagated through the app route and could leave the app screen unavailable.
- Fix: validate renderer output and isolate synchronous renderer errors behind a recoverable per-app error screen with a working back action.
- Source commits: `623e8982ce76c67b6a139801395c31a0c656e13d`, `435bdc03c8d93b65cdea499d8da6fe96d8af4da5`.
- Phone verification: pending.

### Lazy app module failure could become sticky and blank the route
- Symptom: a rejected dynamic `app-screen.js` import stayed cached in `appScreenModulePromise`, so later app opens could immediately repeat the same rejection until a full page reload. The first failed route also had no local recovery UI.
- Fix: clear the cached Promise on import rejection and return a visible Retry/Back recovery screen from the app route.
- Source commit: `2ea49f2d9a8f4e8139001ad273f65f3501625a45`.
- Phone/browser verification: pending.

### Service worker cache cleanup was origin-wide
- Symptom: activation deleted every cache key except the NexusNova cache, which could remove unrelated same-origin web app caches.
- Fix: namespace cleanup to `nexusnova-fresh-shell-*` only and bump NexusNova shell cache to v2.
- Source commit: `953f9767f6f1d6833d17e0ac7f08cae837be6cee`.
- Browser verification: pending.

### Notification click could target an unrelated same-origin tab
- Symptom: `clients.matchAll({includeUncontrolled:true})` could select a same-origin client outside the NexusNova service-worker scope.
- Fix: only focus/navigate clients whose URL belongs to `self.registration.scope`.
- Source commit: `fcfdf2565b543a55b785714d2d3004cde3d459f6`.
- Browser verification: pending.

### Missing Notification API compatibility sentinel was unsafe
- Symptom: old WebViews without `Notification` received a `null` compatibility value. Code that checked `'Notification' in window` could then read `Notification.permission` and throw.
- Fix: use an explicit unsupported sentinel and make the Notifications module detect real constructor support with `typeof globalThis.Notification === 'function'`.
- Source commits: `5f29d00458cce2d482896fe17fda9ddb9062fc23`, `d2ba12b18bf07fd0e41fc6e22c1685b798dea09c`.
- Phone/browser verification: pending.

### Local storage write failure could crash local tools
- Symptom: `saveJson()` called `localStorage.setItem()` directly. Storage quota, privacy mode, or a blocked WebView storage backend could throw from Calendar/Habits/Shopping and other device-local tools.
- Fix: guard the write centrally, return success/failure, and log a warning instead of letting the event handler crash.
- Source commit: `b3bb0aa6697582a256fecb1fcd07c11addf4d9db`.
- Phone verification: pending.

### Wallet EIP-1193 listeners accumulated across screen opens
- Symptom: anonymous `accountsChanged` and `chainChanged` callbacks were registered each time Wallet rendered, but only the Firestore listener was cleaned up.
- Fix: use stable provider handler references and remove both EIP-1193 listeners from `root.__cleanup` while preserving the Firestore unsubscribe.
- Source commit: `eb76a522875e552f82ea3f072eeae47f636c09f0`.
- Phone verification: pending.

### Nova Internet Speed could crash on corrupt saved JSON
- Symptom: `loadPrevious()` safely parsed the saved result, but initialization immediately reparsed the same localStorage value without a guard.
- Fix: return the validated result from `loadPrevious()` and reuse it for initial meter paint; malformed/legacy JSON now falls back to zero safely.
- Source commit: `9255684a94c02c0eb2e398edcf427120ceeb27af`.
- Phone verification: pending.

### Reminders timer could start after the screen was already closed
- Symptom: account-scoped key resolution is asynchronous. If Reminders was closed before it resolved, cleanup ran while `timer` was still null, then the late Promise callback created a detached 15-second interval.
- Fix: add a disposed guard to the async key callback, due checks, drawing and post-permission continuation; cleanup marks the screen disposed before clearing the timer.
- Source commit: `22e86f782bd3cb51aa3aea11999e736280f6ad5e`.
- Phone verification: pending.

### Prayer Times could restart its countdown after screen cleanup
- Symptom: GPS/reverse-geocode/prayer API work could complete after navigation away and then mutate detached DOM or create a new 1-second countdown interval after cleanup.
- Fix: add a disposed lifecycle guard across GPS, city search, prayer loading, status/drawing and the startup microtask; cleanup marks disposed before clearing the interval and immersive classes.
- Source commit: `214ad6f8cf100d59cbd03f14a9de0cd57e81fb14`.
- Phone verification: pending.

## Confirmed bugs still pending

### Qibla async sensor lifecycle can outlive the screen
- File: `fresh-rebuild/src/features/apps/premium-qibla.js`.
- GPS reverse-geocode and `DeviceOrientationEvent.requestPermission()` are asynchronous. They can resume after `root.__cleanup` and re-add orientation listeners or start the Magnetometer on a closed screen.
- The startup microtask can also add the Qibla screen class after an immediate cleanup.
- Planned fix: add one disposed lifecycle guard across the startup microtask, GPS/reverse-geocode continuation, sensor permission continuation, orientation paint and Magnetometer startup. Cleanup must mark disposed before removing/stopping sensors.

### Weather async work can update a closed screen
- File: `fresh-rebuild/src/features/apps/premium-weather.js`.
- Weather has a `cancelled` flag, but initial GPS can still invoke `loadWeather()` after cleanup because the function does not reject cancelled starts.
- The prayer-strip request has no cancelled guard around its late response/error DOM updates, and the weather catch path can also write status after cleanup.
- Planned fix: reject cancelled starts, guard prayer-strip continuations and late error/status updates, while preserving the existing radar cleanup.
