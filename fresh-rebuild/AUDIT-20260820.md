# NexusNova Fresh Rebuild — Structure Audit

Date: 2026-08-20
Branch: `nexusnova-fresh-rebuild-20260820`

## Rebuild contract

- `main` and all Golden/stable backup branches are out of scope and must remain untouched.
- Fresh UI is clean-room. Existing page2 layout, patch stack, legacy 5-tab dock, duplicate headers, blank spacer layouts and old visual components are not design inputs.
- Bottom navigation in the fresh shell has exactly two primary destinations: **MINE** and **NOVA HUB**.
- Existing server/native/economic logic is preserved behind adapters where it is verified and useful.
- Tools Hub is retired as a destination. Its individual tools become first-class Nova Hub apps.
- Final approval is blocked until a fresh-branch Android APK has been built and tested on a real phone.

## Current repository architecture found

### Canonical web surface

- `index.html` — auth/login entry.
- `page2.html` — large historical dashboard/runtime surface.
- `styles.css` + `css/` — base and override styling.
- `js/page2-core.js` — large core dashboard script.
- `js/` — many feature scripts plus historical fixes/guards/overrides.
- `sw.js`, `manifest.webmanifest`, `icons/` — PWA/runtime assets.

### Backend / security

- `functions/` — Firebase callable/server logic including rewarded-ad verification, notifications and Nova Vault logic.
- `firestore.rules` — Firestore policy.
- `firebase.json`, `.firebaserc` — Firebase project/deploy configuration.

### Android

- `NexusNovaAndroid/` — native Android wrapper and bundled web assets.
- Native bridge/security/auth/AdMob work must be treated as a preserved integration surface, not as fresh UI code.

## Main architectural problem in the old frontend

The current UI evolved through many independent patch/override owners. Examples include:

- `nexusnova-allapps-experience-v2.js`
- `nexusnova-allapps-order-guard-v5.js`
- `nexusnova-allapps-scroll-fix-v1.js`
- `nexusnova-allapps-visual-polish-v1.js`
- `nexusnova-compact-premium-v1.js`
- `nexusnova-final-user-fixes-v1.js`
- `nexusnova-mega-merge-v1.js`
- `nexusnova-navigation-stability-v1.js`
- `nexusnova-nine-screen-modern-v1.js`
- `nexusnova-nova-hub-nav-v1.js`
- `nexusnova-premium-ui-v1.js`
- `nexusnova-ux-simplify-v1.js`

This multi-owner structure is the main source of visual regression risk, flash states, selector conflicts, duplicate UI and layout overrides. The fresh rebuild will not stack another patch on top of it.

## Preserve / migrate / retire rules

### Preserve behind adapters

- Firebase Auth/session semantics.
- Firestore security boundaries.
- Server-authoritative mining/reward/value operations.
- Rewarded-ad verification and TEST/production policy separation.
- Existing Android trusted-origin/native bridge work that passes the native audit.
- Existing provider integrations only after their success/error behavior is revalidated.

### Migrate feature-by-feature

- Wallet, Market, Tasks, Profile, Settings.
- Qibla, Speed Test, Weather.
- Browser, AI, News, Travel, Learning, Islamic, Teacher, Documents, Vaults, etc.
- Local-storage tools, with storage keys preserved when safe so user data is not silently discarded.

### Retire from the fresh runtime

- Legacy 5-tab bottom navigation.
- Tools Hub as a nested destination.
- Old page2 visual DOM as a layout dependency.
- UI patch/override scripts as presentation owners.
- Duplicate headers/back bars/search shells.
- Fixed/min-height spacer hacks and black blank areas.
- UI initialization that renders old navigation before replacing it.

## Fresh architecture

The new work lives under `fresh-rebuild/` until migration reaches parity. It is intentionally isolated so the stable runtime remains recoverable while the rebuild is being developed.

```text
fresh-rebuild/
  index.html
  assets/
    styles/
      tokens.css
      app.css
  src/
    main.js
    core/
      router.js
      backend-adapter.js
    components/
      icons.js
      instrument-gauge.js
    features/
      mine/
        mine-screen.js
      hub/
        app-registry.js
        hub-screen.js
```

Future feature folders will follow `features/<app-id>/` and own their own view/controller/service boundaries. Shared logic may live in `core/services/`; no feature may mutate another feature's DOM.

## UI quality gates

- Two-item dock only: MINE + NOVA HUB.
- No legacy dock flash at boot.
- One screen header owner at a time.
- No unexplained vertical spacer greater than the design token allowance.
- No fixed `100vh` content traps; use dynamic viewport units and safe-area insets.
- Touch targets >= 44 px.
- Icons are coherent SVG assets/components, not mixed emoji/icon-font placeholders.
- Instrument gauges use SVG geometry, calibrated ticks, smooth needle motion, readable values and reduced-motion fallback.
- No fake financial/provider data. Unavailable data is explicitly shown as unavailable.
- Every async app has loading, success, empty and error states.

## Migration order

1. Fresh shell + design tokens + router + icon system.
2. Mining screen structure + backend adapter contract.
3. Nova Hub registry and direct Tools Hub split.
4. Core economic apps: Wallet, Tasks, Market.
5. High-device-value apps: Qibla, Speed Test, Weather, Browser.

8. Remove legacy runtime from the fresh entry only after parity tests pass.
9. Sync Android bundled web assets for the fresh branch.
10. Build TEST APK, run phone test, fix phone-only issues.
11. Only after phone approval, prepare production/release migration.
